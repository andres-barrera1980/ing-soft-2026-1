Patrón de Diseño: Builder

Categoría: Gamma (GoF)
Tipo: Creacional

1. Contexto: Categoría Gamma (GoF)

Este patrón pertenece a la clasificación establecida por Erich Gamma y sus coautores en el libro fundamental "Design Patterns" (1994). Son conocidos como la "Gang of Four" (Erich Gamma, Richard Helm, Ralph Johnson y John Vilssides).

2. Tipo: Creacional

Los patrones Creacionales se enfocan en los mecanismos de creación de objetos. Su objetivo es aumentar la flexibilidad y la reutilización del código existente.

  • Evitan el uso excesivo de new disperso por todo el código.
  • Aislar cómo se crean los objetos de cómo se usan.
  • Son fundamentales para sistemas que deben ser independientes de cómo se crean sus componentes.

3. El Patrón Builder

Definición

Es un patrón que permite construir objetos complejos paso a paso. A diferencia de otros patrones creacionales, el Builder no requiere que el producto final tenga una interfaz común, lo que permite crear productos muy diferentes siguiendo el mismo proceso.

Estructura (Participantes)

  • Director: Gestiona el orden de los pasos de construcción.
  • Builder (Interfaz): Define los pasos necesarios para construir el producto.
  • Builder Concreto: Implementa los pasos específicos y retiene el producto resultante.
  • Producto: El objeto complejo que estamos construyendo.

4. Ejemplo de Código (C++)

Un ejemplo claro aplicando la construcción de una computadora personalizada:

// Producto Final
class PC {
public:
    string cpu, ram;
    void mostrar() { cout << "PC con " << cpu << " y " << ram << endl; }
};

// Interfaz Builder
class PCBuilder {
public:
    virtual void setCPU() = 0;
    virtual void setRAM() = 0;
    virtual PC* getResult() = 0;
};

// Builder Concreto
class GamerPCBuilder : public PCBuilder {
    PC* pc = new PC();
public:
    void setCPU() override { pc->cpu = "Intel i9"; }
    void setRAM() override { pc->ram = "32GB"; }
    PC* getResult() override { return pc; }
};

// Director
class Fabricante {
public:
    void construir(PCBuilder* b) {
        b->setCPU();
        b->setRAM();
    }
};

5. ¿Cuándo usarlo?

  • Cuando el constructor de una clase tiene demasiados parámetros
  • Cuando queremos que el código sea capaz de crear distintas representaciones de un objeto (ej. JSON, XML, HTML) usando el mismo proceso de construcción.
  • Cuando la construcción de un objeto implica pasos complejos que deben ejecutarse en un orden específico.
