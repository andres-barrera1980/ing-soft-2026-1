Patrones de Comportamiento

El patrón de Estado es una pieza fundamental de los 11 patrones de comportamiento definidos por el Gang of Four (GoF).

Estos patrones gestionan algoritmos y la asignación de responsabilidades entre objetos, optimizando la comunicación en sistemas complejos.

"Permite que un objeto altere su comportamiento cuando su estado interno cambia. El objeto parecerá haber cambiado de clase."
— Erich Gamma, Richard Helm, Ralph Johnson, John Vlissides

La Necesidad Técnica

El "Switch Statement Hell"

Sin este patrón, la lógica de estado suele residir en grandes bloques condicionales que son difíciles de testear y mantener.

La Solución Polimórfica

El patrón Estado transforma cada rama de la condicional en una clase independiente, delegando la responsabilidad a objetos de estado especializados.

Estructura del Sistema

Contexto

Mantiene la referencia al estado actual y define la interfaz para los clientes.

Estado

Interfaz común que encapsula el comportamiento ligado a una fase del contexto.

Concretos

Implementaciones reales donde reside la lógica específica de cada fase o estado.

Ejemplo de Código

Contexto: AudioPlayer

El reproductor delega el comportamiento a una interfaz AudioState.

Al presionar 'Play', el reproductor no pregunta su estado; simplemente llama a state.clickPlay(), y el objeto activo decide la acción.

interface AudioState {
  void clickPlay(AudioPlayer player);
}

class PlayingState implements AudioState {
  public void clickPlay(AudioPlayer p) {
    p.changeState(new ReadyState());
    p.stopPlayback();
  }
}

class AudioPlayer {
  private AudioState state;
  public void play() {
    state.clickPlay(this);
  }
}

Balance de Implementación

Ventajas (Pros) Desventajas (Contras)
Responsabilidad Única: Lógica de estados aislada. Aumento en la cantidad de clases del sistema.
Abierto/Cerrado: Nuevos estados sin riesgos. Puede ser excesivo para máquinas simples.
Elimina transiciones implícitas y errores de lógica. Requiere arquitectura clara de comunicación.
