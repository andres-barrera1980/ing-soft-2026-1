// 01 — Definición
¿Qué es?
"

Abstract Factory provee una interfaz para crear familias de objetos relacionados o dependientes sin especificar sus clases concretas.

01

Catálogo

Gang of Four (GoF) — uno de los 23 patrones clásicos del libro Design Patterns de 1994.

02

Analogía

Es como una fábrica de muebles: si eliges estilo "moderno", todos los muebles serán modernos y compatibles.

03

Alias

También conocido como Kit. Cuando escuchas "fábrica de fábricas", se refieren a este patrón.

// 03 — Implementación
Código Java
Fábrica abstracta + Concretas
// Interfaz abstracta
interface UIFactory {
  Button   createButton();
  Checkbox createCheckbox();
}

// Fábrica concreta: Tema Claro
class LightFactory implements UIFactory {
  public Button createButton() {
    return new LightButton();
  }
  public Checkbox createCheckbox() {
    return new LightCheckbox();
  }
}

// Fábrica concreta: Tema Oscuro
class DarkFactory implements UIFactory {
  public Button createButton() {
    return new DarkButton();
  }
  public Checkbox createCheckbox() {
    return new DarkCheckbox();
  }
}
Productos + Cliente
// Productos abstractos
interface Button   { void paint(); }
interface Checkbox { void paint(); }

// Productos concretos
class LightButton implements Button {
  public void paint() {
    System.out.println("Botón claro");
  }
}
class DarkButton implements Button {
  public void paint() {
    System.out.println("Botón oscuro");
  }
}

// Cliente desacoplado
class App {
  private UIFactory factory;

  App(UIFactory factory) {
    this.factory = factory;
  }
  void render() {
    Button   btn = factory.createButton();
    Checkbox chk = factory.createCheckbox();
    btn.paint();
    chk.paint();
  }
}

Ventajas, Desventajas y Comparación

▸

// 05 — Aplicación
¿Cuándo Usar Abstract Factory?
Un patrón no se aplica siempre. Usar uno donde no corresponde es igual de malo que no usarlo donde sí corresponde.
01
Independencia de creación

Cuando el código de negocio no debe cambiar si mañana cambian las implementaciones concretas.

Ej: migrar de MySQL a PostgreSQL sin tocar el código cliente.
02
Familias de productos juntos

Cuando el sistema trabaja con múltiples familias de objetos que deben usarse en conjunto.

Ej: tema claro y oscuro, cada uno con sus propios componentes.
03
Revelar solo interfaces

Cuando construyes una biblioteca o SDK y quieres exponer interfaces sin revelar las implementaciones internas.

Ej: le das la fábrica abstracta al desarrollador, no las clases concretas.
⚠
Señal de alerta — momento de usar el patrón

Cuando te encuentras escribiendo muchos bloques if-else o switch-case que dicen: "si es modo oscuro, crea esto; si es modo claro, crea aquello." Esos condicionales son exactamente el problema que Abstract Factory resuelve.
