01. Introducción

En la ingeniería de software, representar jerarquías complejas suele ser un reto arquitectónico. El patrón Composite surge como la solución definitiva para manejar estructuras tipo árbol, permitiendo que el sistema ignore la distinción técnica entre un objeto individual y un grupo de objetos. Esta abstracción reduce drásticamente la presencia de condicionales y acoplamiento innecesario.

02. ¿Qué es el Patrón Composite?

Es un patrón de diseño estructural que permite componer objetos en estructuras de árbol para representar jerarquías de "parte-todo". Su esencia radica en que tanto los componentes básicos (Hojas) como los contenedores (Compuestos) comparten una interfaz común. Esto permite que el código cliente sea agnóstico a la estructura interna del árbol, tratando a cada nodo con el mismo respeto y protocolo.

03. Características

Recursividad

Contenedores que pueden albergar otros contenedores.

Uniformidad

Trato igualitario para hojas y compuestos.

Transparencia

El cliente desconoce la estructura interna.

Jerarquía

Representación perfecta de "Parte-Todo".

06. Implementación en Java

Código fuente diseñado siguiendo el contrato del patrón:

// Componente: Define el contrato común para todos los nodos
interface SistemaArchivo {
    void listar(String indentacion);
}

// Hoja: Elemento terminal que realiza el trabajo real
class Archivo implements SistemaArchivo {
    private String nombre;

    public Archivo(String nombre) { this.nombre = nombre; }

    @Override
    public void listar(String indent) {
        System.out.println(indent + "📄 " + nombre);
    }
}

// Composite: Contenedor que gestiona una lista de componentes
import java.util.*;

class Carpeta implements SistemaArchivo {
    private String nombre;
    private List<SistemaArchivo> contenidos = new ArrayList<>();

    public Carpeta(String nombre) { this.nombre = nombre; }

    public void agregar(SistemaArchivo sa) { contenidos.add(sa); }

    @Override
    public void listar(String indent) {
        System.out.println(indent + "📂 [" + nombre + "]");
        for (SistemaArchivo item : contenidos) {
            item.listar(indent + "   ");
        }
    }
}

07. Recorrido del Árbol

Puedes recorrer el árbol de varias formas dependiendo de tus necesidades:

Depth First Search (DFS)

Explora lo más profundo posible por cada rama antes de retroceder. Es la forma más natural y eficiente para jerarquías recursivas, ya que utiliza la pila de llamadas del sistema.

Breadth First Search (BFS)

Explora nivel por nivel (primero todos los hijos directos, luego los nietos). Funciona procesando los nodos de forma horizontal antes de bajar al siguiente nivel de profundidad.

08. Ventajas y Desventajas

✔️ Ventajas

  • Polimorfismo: Permite recorrer estructuras complejas recursivamente con una sola llamada inicial.
  • Escalabilidad: Se pueden agregar nuevas clases Hoja o Compuesto sin modificar el cliente.
  • Código Limpio: Elimina bloques repetitivos de validación de tipos de objetos.

❌ Desventajas

  • Dificultad de Restricción: Puede ser complejo limitar qué tipos de hijos se permiten en un compuesto específico.
  • Sobrediseño: En jerarquías muy simples, puede añadir una capa de abstracción innecesaria.
