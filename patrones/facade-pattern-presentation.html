Definición

¿Qué es Facade?

"Provee una interfaz unificada a un conjunto de interfaces en un subsistema. Facade define una interfaz de nivel superior que hace el subsistema más fácil de usar."

Los subsistemas no conocen al Facade
  • Facade — conoce qué clases del subsistema son responsables de cada solicitud y delega en ellas.
  • Clases del subsistema — implementan la funcionalidad real; no guardan referencias al Facade.
03 / 09
Implementación

Facade en Java

// Subsistema: clases internas del compilador
class Scanner  { Token scan()  { /* ... */ } }
class Parser   { void parse(Scanner s, Builder b) { /* ... */ } }
class Builder  { ProgramNode getRootNode() { /* ... */ } }
class Generator{ void generate(ProgramNode n) { /* ... */ } }

// ◆ FACADE — interfaz simplificada
public class Compiler {
    public void compile(InputStream src, OutputStream out) {
        Scanner   scanner   = new Scanner(src);
        Builder   builder   = new Builder();
        Parser    parser    = new Parser();
        Generator generator = new Generator(out);

        parser.parse(scanner, builder);
        builder.getRootNode().traverse(generator); // ¡todo en un método!
    }
}

// Cliente — solo necesita saber de Compiler
new Compiler().compile(input, output);
04 / 09
Aplicabilidad

¿Cuándo usarlo?

  • Subsistema complejo El sistema creció y tiene muchas clases pequeñas. El Facade provee una vista por defecto suficiente para la mayoría.
  • Muchas dependencias Clientes acoplados a clases de implementación. Facade desacopla y mejora la portabilidad.
  • Arquitectura por capas Define el punto de entrada de cada capa; si son dependientes, comunícalas solo a través de sus facades.

📌 Regla de oro: Si un cliente necesita instanciar y coordinar más de 3 clases solo para realizar una operación común → es momento de un Facade.

05 / 09
Consecuencias

Ventajas y Desventajas

✓ Ventajas

  • Reduce el número de objetos que el cliente maneja.
  • Promueve acoplamiento débil entre subsistema y clientes.
  • Elimina dependencias circulares y simplifica la compilación.
  • Facilita el porting a otras plataformas.
  • No oculta las clases internas: el acceso directo sigue disponible.

✗ Desventajas / Limitaciones

  • Puede convertirse en un God Object si acumula demasiada lógica.
  • Si el Facade crece, viola el principio de responsabilidad única.
  • Añade una capa de indirección que puede ocultar problemas de diseño.
  • Para clientes avanzados, puede ser un obstáculo innecesario.
06 / 09
Implementación

Consideraciones clave

  • Facade abstracto Hacer el Facade abstracto con subclases concretas permite intercambiar implementaciones del subsistema sin que el cliente lo sepa.
  • Configuración por composición Alternativamente, inyectar los objetos del subsistema al Facade (DI) permite personalizar sin herencia.
  • Visibilidad pública/privada El Facade es público, pero otras clases del subsistema pueden ser de alcance de paquete (package-private en Java), restringiendo el acceso accidental.
  • Instancia única Generalmente solo se necesita un Facade → candidato natural para aplicar el patrón Singleton.
07 / 09
Patrones Relacionados

Facade vs. otros patrones

Abstract Factory

Puede usarse junto a Facade para crear los objetos del subsistema de forma independiente a la plataforma. También es alternativa para ocultar clases específicas.

Mediator

Ambos abstraen funcionalidad, pero Mediator centraliza comunicación entre colegas (que sí lo conocen). Facade solo simplifica el acceso; los subsistemas no lo conocen.

Singleton

Facade suele implementarse como Singleton porque normalmente basta con una sola instancia que represente el punto de entrada al subsistema.

Adapter

Adapter convierte una interfaz en otra compatible. Facade agrupa múltiples interfaces bajo una nueva más simple. Propósito diferente, resultado similar.

Builder (en el ejemplo)

ProgramNodeBuilder interactúa con Parser según el patrón Builder; Facade los orquesta sin que el cliente conozca ese detalle.

Visitor (en el ejemplo)

CodeGenerator es un Visitor que recorre el árbol de ProgramNodes; de nuevo, Facade oculta esta complejidad al cliente.

✓
Resumen

Puntos Clave

  • Provee una interfaz unificada y simple a un subsistema complejo.
  • Reduce el acoplamiento entre cliente y subsistema sin eliminar el acceso directo.
  • Ideal cuando el subsistema creció o tiene muchas dependencias cruzadas.
  • En Java: visibilidad package-private + DI refuerzan el patrón.
  • Cuidado con el God Object: el Facade debe delegar, no implementar.
  • Se complementa con Singleton, Abstract Factory y Mediator.

💡 "El Facade facilita la vida a la mayoría sin ocultar la potencia a quienes la necesitan." — GoF
