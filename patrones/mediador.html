Patrón
Chain of Responsibility

Deja de escribir bloques interminables de if-else. Aprende a pasar "la papa caliente" con elegancia en tu código.

¿Qué es y cómo funciona?

El patrón Cadena de Responsabilidad (Comportamiento) te permite pasar solicitudes a lo largo de una cadena de manejadores (handlers).

Al recibir una solicitud, cada manejador decide si la procesa o si la pasa al siguiente manejador en la cadena. ¡Es como un filtro en cascada!

¡La Analogía!

Call Center de Soporte Técnico 🎧

  1. 1 Llamas porque tu internet no funciona. Responde un Bot (Nivel 1).
  2. 2 Si es solo reiniciar, el bot lo arregla. Si no, te pasa con un Humano (Nivel 2).
  3. 3 Si el humano detecta que hay un cable roto en tu cuadra, lo pasa a los Técnicos de Calle (Nivel 3).

Tú (el cliente) no necesitas saber quién lo arregla, solo quieres que la cadena encuentre al responsable.

Los Participantes

Handler

Define una interfaz (o clase abstracta) para tratar las peticiones. Opcionalmente implementa el enlace al sucesor.

ConcreteHandler

Maneja la petición si es su responsabilidad; de lo contrario, la reenvía a su sucesor en la cadena.

Client

Inicia la petición al primer objeto ConcreteHandler de la cadena. ¡No sabe qué objeto la resolverá finalmente!

¡Manos a la obra! (Ejemplo en Java)

Vamos a codificar nuestro ejemplo del Call Center. Fíjate cómo logramos bajo acoplamiento al no conectar el cliente directamente con los niveles superiores.

CallCenterSupport.java 

// 1. La clase Handler abstracta
abstract class SupportHandler {
    protected SupportHandler nextHandler;

    public void setNextHandler(SupportHandler nextHandler) {
        this.nextHandler = nextHandler;
    }

    public abstract void handleRequest(String issueSeverity);
}

// 2. ConcreteHandler: Nivel 1 (Bot)
class Level1Support extends SupportHandler {
    @Override
    public void handleRequest(String issueSeverity) {
        if (issueSeverity.equals("LOW")) {
            System.out.println("🤖 Bot Nivel 1: Problema resuelto. Por favor reinicie su router.");
        } else if (nextHandler != null) {
            System.out.println("🤖 Bot Nivel 1: Es muy complejo. Pasando a humano...");
            nextHandler.handleRequest(issueSeverity);
        }
    }
}

// 2. ConcreteHandler: Nivel 2 (Humano)
class Level2Support extends SupportHandler {
    @Override
    public void handleRequest(String issueSeverity) {
        if (issueSeverity.equals("MEDIUM")) {
            System.out.println("👨‍💻 Agente Nivel 2: He reconfigurado sus credenciales. Problema resuelto.");
        } else if (nextHandler != null) {
            System.out.println("👨‍💻 Agente Nivel 2: Necesitamos enviar técnicos. Escalando...");
            nextHandler.handleRequest(issueSeverity);
        }
    }
}

// 2. ConcreteHandler: Nivel 3 (Terreno)
class Level3Support extends SupportHandler {
    @Override
    public void handleRequest(String issueSeverity) {
        if (issueSeverity.equals("HIGH")) {
            System.out.println("🚐 Equipo Nivel 3: Vamos en camino a reparar la fibra óptica cortada.");
        } else {
            System.out.println("❌ Soporte: El problema no puede ser manejado.");
        }
    }
}

// 3. Client: ¡Haciendo las llamadas!
public class Main {
    public static void main(String[] args) {
        // Configuramos la cadena
        SupportHandler bot = new Level1Support();
        SupportHandler agent = new Level2Support();
        SupportHandler fieldTeam = new Level3Support();

        bot.setNextHandler(agent);
        agent.setNextHandler(fieldTeam);

        // Simulamos clientes
        System.out.println("--- Cliente 1 (No le carga Netflix) ---");
        bot.handleRequest("LOW");

        System.out.println("\n--- Cliente 2 (Se le desconfiguró la IP) ---");
        bot.handleRequest("MEDIUM");

        System.out.println("\n--- Cliente 3 (Un camión rompió el cable en su calle) ---");
        bot.handleRequest("HIGH");
    }
}

Pros y Contras (El Análisis Crítico)

Ventajas

  • ✔ Reduce el acoplamiento: El cliente no sabe qué clase específica manejará su petición.
  • ✔ Principio Open/Closed: Puedes introducir nuevos manejadores en el código sin romper el cliente existente.
  • ✔ Flexibilidad: Puedes alterar dinámicamente la cadena de responsabilidades en tiempo de ejecución.

Desventajas

  • ✖ Recepción no garantizada: Si la petición llega al final de la cadena y nadie la atiende, se perderá silenciosamente.
  • ✖ Trazabilidad difícil: Debuggear una cadena muy larga para saber dónde falló algo puede dar dolores de cabeza.
  • ✖ Costos de rendimiento: Aunque mínimos, recorrer una cadena profunda puede impactar tiempos de respuesta.
