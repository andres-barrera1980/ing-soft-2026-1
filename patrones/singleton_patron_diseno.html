SCROLL
01 · Definición

¿Qué es el Singleton?

Garantiza que una clase tenga una sola instancia y proporciona un punto de acceso global a ella.

🔒

Una sola instancia

Restringe la creación de múltiples objetos de la misma clase en toda la aplicación.

Gang of Four · Design Patterns (1994)
🔑

Acceso global

Provee un punto de acceso único y controlado desde cualquier parte del código.

🛡️

Lazy initialization

El objeto se crea solo cuando se necesita por primera vez — inicialización diferida.

02 · Estructura

Diagrama UML

«class» Singleton
Atributos
- instance: Singleton
Métodos
- Singleton()
+ getInstance(): Singleton

Constructor privado

Impide que otras clases instancien el objeto directamente con new.

Atributo estático

Almacena la única instancia; es propiedad de la clase, no de un objeto.

Método getInstance()

Punto de acceso global. Crea la instancia si no existe, o la retorna.

03 · Código

Implementación en múltiples lenguajes

Singleton.java · Implementación Thread-Safe
public class Singleton {
  private static volatile Singleton instance;

  private Singleton() {} // Constructor privado

  public static synchronized Singleton getInstance() {
    if (instance == null) {
      instance = new Singleton();
    }
    return instance;
  }
}

volatile

Garantiza visibilidad entre hilos (thread-safe).

synchronized

Bloqueo para evitar condiciones de carrera.

Constructor privado

Evita instanciación externa.

Lazy loading

Instancia creada solo en la primera llamada.

⚠ Double-Checked Locking es preferible para mejor rendimiento en Java 5+

class SingletonMeta(type):
  _instances = {}

  def __call__(cls, *args, **kw):
    if cls not in cls._instances:
      cls._instances[cls] = \

04 · Casos de Uso

¿Dónde se usa el Singleton?

🖨️

Logger / Sistema de Log

Un único sistema de registro evita conflictos de escritura y garantiza consistencia en los registros.

🗄️

Pool de Conexiones BD

Gestión centralizada de conexiones a bases de datos. Evita crear múltiples conexiones costosas.

⚙️

Configuración Global

Lectura de archivos .env o config.json una sola vez; accesible desde cualquier módulo.

🎮

Game Manager

En videojuegos, maneja el estado global: puntuación, vidas, nivel actual y configuración.

🔀

Cache / Estado Compartido

Almacén de caché en memoria compartido entre componentes sin duplicar datos.

🛡️

Auth Manager

Gestión de sesión de usuario: token, permisos y estado de autenticación centralizado.

05 · Análisis Crítico

Ventajas y Desventajas

✔  VENTAJAS
Garantiza una única instancia en toda la app
Acceso global sin necesidad de pasar referencias
Lazy initialization: ahorra recursos si no se usa
Control centralizado del recurso compartido
Fácil de implementar en la mayoría de lenguajes
✘  DESVENTAJAS
Dificulta las pruebas unitarias (mocking complejo)
Introduce estado global — viola principio SRP
Problemas en entornos multihilo si no es thread-safe
Acoplamiento oculto entre módulos
Considerado anti-patrón en algunos contextos
05 · Alternativas

¿Cuándo usar algo diferente?

Singleton hace... Mejor alternativa Beneficio
Estado global mutableInyección de Dependencias (DI)Más testeable, bajo acoplamiento
Cache compartidaContext / Provider (React, etc.)Scope controlado, sin estado global
Config del sistemaMódulo / Namespace exportadoInmutable, carga única sin clase
Pool de conexionesFactory + IoC ContainerCiclo de vida gestionado por framework
💡 El Singleton no está mal; el problema es usarlo cuando no se necesita estado global real.
06 · Conclusiones

Lo que debes recordar

1

Úsalo cuando necesites realmente una instancia única

Logging, configuración, conexiones BD son buenos candidatos.

2

Hazlo thread-safe desde el inicio

volatile + synchronized en Java; locks en Python para entornos concurrentes.

3

Evítalo si solo buscas comodidad

Estado global oculta dependencias y dificulta el testing.

4

Considera la Inyección de Dependencias (DI)

En proyectos grandes, un IoC container gestiona mejor el ciclo de vida.

Singleton es un patrón clásico del GoF — úsalo con criterio, no como conveniencia.
