Patrón Adapter

también conocido como <Wrapper>

Este patrón tiene como objetivo convertir la interfaz de una clase en otra interfaz que los clientes esperan. Su función principal es permitir que clases con interfaces incompatibles trabajen juntas, actuando como un puente entre una funcionalidad existente y una necesidad específica del sistema.

¿Cómo funciona?

  1. Solicitud del Cliente: El cliente realiza una llamada a una operación sobre la instancia del Adaptador utilizando la interfaz conocida (Target).
  2. Traducción y Redirección: El Adaptador recibe la petición y la traduce internamente para llamar a los métodos específicos de la clase preexistente (Adaptee).
  3. Ejecución en el Adaptado: La clase preexistente realiza el trabajo real utilizando su propia interfaz original sin saber que está siendo adaptada.
  4. Entrega de Resultados: Si es necesario, el Adaptador procesa la respuesta de la clase adaptada para que coincida con el formato que el cliente espera recibir.

Código comentado línea a línea

Cada sección del código explicada junto a lo que hace.

Parte 1 — Interfaz Target
Target / Contrato
// Define qué métodos debe tener cualquier "Forma" interface Forma { // Método para dibujar la forma en pantalla void draw(); // Método para obtener el área de la forma double getArea(); }
¿Qué es una interface? Es un contrato. Cualquier clase que lo firme está obligada a implementar todos sus métodos.
draw() Declara que toda Forma debe saber dibujarse. No define cómo, solo dice que debe poder hacerlo.
getArea() Declara que toda Forma debe poder calcular su área y devolver un número decimal (double).
Parte 2 — Clase Adaptee
Adaptee / Clase externa
// Clase existente con su propia interfaz class ComponenteTextoExterno { // Devuelve {ancho, alto} del texto como arreglo public int[] getBoundingBox() { System.out.println("Calculando bounding box..."); return new int[] {200, 50}; } // Renderiza el texto usando su propio sistema public void renderText() { System.out.println("Renderizando texto externo..."); } }
¿Por qué es incompatible? Esta clase no implementa Forma. Sus métodos se llaman diferente: renderText() en vez de draw(), y getBoundingBox() en vez de getArea().
getBoundingBox() Devuelve un arreglo de 2 números: la posición 0 es el ancho y la posición 1 es el alto del texto. El Adapter usará esto para calcular el área.
renderText() Es el equivalente del draw(), pero con otro nombre. El Adapter se encargará de conectarlos.
Parte 3 — Clase Adapter
Adapter / El puente
// Implementa Forma (cumple el contrato del cliente) class AdaptadorTexto implements Forma { // Guarda una referencia al objeto externo private ComponenteTextoExterno texto; // Constructor: recibe el objeto a adaptar public AdaptadorTexto(ComponenteTextoExterno t) { this.texto = t; } // draw() del contrato → llama a renderText() del externo @Override public void draw() { texto.renderText(); } // getArea() del contrato → usa getBoundingBox() y calcula @Override public double getArea() { int[] dims = texto.getBoundingBox(); return dims[0] * dims[1]; // ancho × alto } }
implements Forma Al implementar la interfaz, esta clase se compromete a tener draw() y getArea(). Así el Cliente puede usarla como si fuera cualquier otra Forma.
private ComponenteTextoExterno texto Guarda el objeto externo adentro. Es el "envuelto". El Adapter lo usa internamente pero el Cliente nunca lo ve.
Constructor Al crear el Adapter, se le pasa el objeto externo que se quiere adaptar. Esto es la inyección del Adaptee.
draw() → renderText() Cuando el Cliente llama draw(), el Adapter lo redirige a renderText(). Traducción directa de un método al otro.
getArea() → getBoundingBox() El Adapter pide las dimensiones al objeto externo, y él mismo hace la multiplicación. El Cliente recibe el área sin saber cómo se obtuvo.
Parte 4 — Cliente
Client / Uso final
public class EditorGrafico { public static void main(String[] args) { // Crea el objeto externo (la librería incompatible) ComponenteTextoExterno lib = new ComponenteTextoExterno(); // Lo envuelve en el Adapter → ahora es una Forma válida Forma miTexto = new AdaptadorTexto(lib); // El editor usa la interfaz Forma sin saber qué hay detrás miTexto.draw(); // Imprime el área sin conocer getBoundingBox() System.out.println("Área: " + miTexto.getArea()); } }
new ComponenteTextoExterno() Se instancia la librería externa. En la práctica, esto podría venir de una dependencia o módulo ya existente.
Forma miTexto = new AdaptadorTexto(lib) Aquí ocurre la clave: la variable es de tipo Forma, pero lo que hay adentro es un AdaptadorTexto que envuelve la librería. El tipo de la variable oculta la complejidad.
miTexto.draw() y miTexto.getArea() El editor solo llama métodos de Forma. No sabe nada de renderText() ni de getBoundingBox(). La incompatibilidad quedó completamente oculta.

Ventajas

♻️

Reutilización de clases

Permite usar clases existentes cuya interfaz no coincide, sin modificar código ajeno o legado.

🔧

Módulos reutilizables

Facilita crear módulos que cooperan con clases no previstas o interfaces aún no definidas.

🌿

Flexibilidad (Object Adapter)

Un solo adaptador puede trabajar con una clase y todas sus subclases simultáneamente.

👁️

Transparencia al cliente

El cliente ignora completamente las diferencias de interfaz de los objetos que usa.

Desventajas

📡

Indirección adicional

Introduce un nivel extra de llamadas; en sistemas críticos puede tener impacto en rendimiento.

🔒

Rigidez en herencia (Class Adapter)

El adaptador de clases se compromete con una clase específica y no adapta a subclases.

🧩

Dificultad para sobrescribir

En el adaptador de objetos, sobrescribir comportamientos requiere subclases adicionales.

Conclusión

Úsalo para resolver incompatibilidades: El Adapter es la herramienta ideal cuando descubres que dos clases que deberían trabajar juntas no pueden hacerlo por discrepancias en sus métodos. Es un patrón que suele aplicarse después de que el código ha sido diseñado, como una solución a problemas de integración imprevistos.

No lo confundas: A diferencia del Bridge, que se diseña antes para que las cosas varíen independientemente, el Adapter se aplica para que cosas que ya existen funcionen juntas a pesar de sus diferencias.
